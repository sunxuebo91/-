# 收钱吧微信小店代客下单集成方案

> 用「代客下单」新流程**替换**当前 baobei 内被注释/死代码的支付宝收银台体验。

> **方案 C**：CRM 加 2 个端点（`baobei-precreate` + `refund-confirm`），让 `payment_records` 保持 single source of truth。

---

## 1. 背景

### 当前 baobei 支付宝支付现状

| 位置 | 状态 |
|---|---|
| `myOrders/detail.wxml` 浮底按钮 | 调的是 `goCheckout`（收银台 webview） |
| `myOrders/detail.js` `goAlipay` + `alipay` 状态 + wxml 弹窗模板 | **死代码**（无任何 UI 入口触发） |
| `paymentService/precreateGateway` + `payway=1` 支付宝 | 云函数层 alive，但前端无入口 |
| `paymentService/index.js` `ALIPAY_RETURN_URL = 'https://example.com/'` | 占位符，体验差 |
| 体验痛点 | baobei webview 拦截 `alipays://` 协议，客户扫码后跳转失败率高 |

### 收钱吧技术提供的替代方案

**微信小店代客下单 API**（25 页 PDF，已读）：
- 商家系统调用「创建代客下单」生成 `preOrderId`
- 调用「生成 H5 短链 / 扫码链接」生成支付入口
- 客户在浏览器/微信/支付宝扫码付
- 收钱吧主动推送订单/退款状态到我们回调
- **真正支持支付宝，体验顺畅**（客户在支付宝 APP 内完成，无需跳转拦截）

## 2. 设计决策（已老板拍板 2026-07-09）

| 决策点 | 选择 | 备注 |
|---|---|---|
| **发起方** | **A** 销售在 baobei 端发起 | PDF「代客下单」场景，销售主导；客户只扫码 |
| **替换 vs 双轨** | **完全替换** | 原 `goAlipay` 是死代码，无用户感知；保留只增加维护负担 |
| **CRM 改动策略** | **方案 C**（+2 端点） | `payment_records` 保持 single source of truth，baobei 不越权写 DB |
| **生产配置** | ⏸️ 老板找收钱吧技术拿生产 mallSn/签名/公钥 | 测试参数 PDF 已有，可先用 |

## 3. 架构

### 3.1 流程

```
销售端（baobei）                    云函数                  CRM 端点             收钱吧            客户
─────────────────               ────────                ─────────            ────────          ────────
点「代客下单」                                                                            
   │
   ├─→ paymentService.createPreOrder  ──→ POST /preOrder/createPreOrder  ───────────→
   │                                            │
   │                                            └─→ preOrderId
   │
   ├─→ baobei 调 CRM /api/payment-records/baobei-precreate (X-Service-Secret) ──→ CRM 写 payment_records (pending)
   │                                                                                       │
   │                                                                                       └─→ 返 { recordId, clientSn }
   │
   ├─→ paymentService.generateShareUrl ──→ POST /preOrder/generatePreOrderShareUrl ───→
   │                                            │
   │                                            └─→ shareUrl → 上传云存储 → qrCodeFileId
   │
   └─→ 弹二维码 / 分享短链到微信
                                                                  用户扫码（支付宝/微信） ──┐
                                                                                            │
                                                                                       支付完成
                                                                                            │
                                                                                            ▼
                                                  POST 推到 baobei paymentCallback (云函数 HTTP trigger)
                                                            │
                                                            ▼
                                              SHA256WithRSA 验签 + 落库 baobei payments
                                                            │
                                                            ▼
                                              POST CRM /api/miniprogram/contracts/{id}/payment-confirm
                                                       (4 fields: phone/amount/sqb_sn/paidAt)
                                                            │
                                                            ▼
                                                       CRM 标 payment_records.status=paid
```

### 3.2 baobei 新增的 actions / 接口

| 位置 | action / 接口 | 调收钱吧接口 / 用途 | 入参 | 出参 |
|---|---|---|---|---|
| `paymentService` | `createPreOrder` | SQB `/preOrder/createPreOrder` | `{ contractId, phone, paymentSequenceNo?, amountCents, subject }` | `{ preOrderId, preOrderSn }` |
| `paymentService` | `queryPreOrder` | SQB `/preOrder/queryPreOrder` | `{ preOrderId }` | `{ status, paidAmount, paidAt }` |
| `paymentService` | `generatePreOrderShareUrl` | SQB `/preOrder/generatePreOrderShareUrl` | `{ preOrderId, pageType=5, imageType=1 }` | `{ shareUrl, qrCodeFileId }` |
| `paymentService` | `generatePreOrderH5Link` | SQB `/preOrder/generatePreOrderH5Link` | `{ preOrderId, pageType=5 }` | `{ h5Url }` |
| `paymentService` | `refundPreOrder` | SQB `/refund` | `{ preOrderId, amountCents, reason }` | `{ refundSn }` |
| `paymentCallback` (新建云函数, HTTP trigger) | — | 收钱吧推送 (订单/退款) + signature | 推送 payload | `{ code: 0 }` |

### 3.3 CRM 新增的端点

| 端点 | 鉴权 | 入参 | 出参 | 用途 |
|---|---|---|---|---|
| `POST /api/payment-records/baobei-precreate` | X-Service-Secret | `{ phone, contractId, orderCategory, paymentSequenceNo?, amountCents, subject, channel }` | `{ recordId, clientSn }` | baobei 代客下单前，CRM 先建 payment_records pending 行 |
| `POST /api/contracts/:id/refund-confirm` | X-Service-Secret | `{ phone, paymentRecordId?, sqbRefundSn, refundAmountCents, refundedAt }` | `{ ok: true }` | baobei SQB 退款成功后，CRM 标 refunded + 累加 contract.refundAmount |

### 3.4 CRM 已有端点（直接用，0 改动）

| 端点 | 用途 |
|---|---|
| `POST /api/miniprogram/contracts/{id}/payment-confirm` | baobei webhook 收到 SQB 推送后调，body 4 字段（phone/amount/sqb_sn/paidAt），**不带 channel/payway** |

### 3.5 鉴权

**收钱吧新流程**：
- 请求：MD5(body + appkey)，`Authorization: {appid} {sign}`
- 响应/回调验签：SHA256WithRSA，PKCS#8 公钥

**CRM 新端点**：
- `X-Service-Secret`（与现有 `payment-confirm` 一致）

### 3.6 数据库

**baobei `payments` 集合**新增字段（与 CRM payment_records 区分，baobei 内部用）：
```js
{
  // ... 现有字段 ...
  payMode: 'preorder_alipay' | 'preorder_wechat',   // 替换 'gateway_alipay'
  preOrderId: '',                // 收钱吧预订单号 (SQB clientSn)
  preOrderSn: '',                // 收钱吧订单编码
  channel: 'alipay' | 'wechat',  // 客户扫码后实际走的通道
  paidAmountCents: 0,
  paidAt: Date,
  crmRecordId: '',              // CRM 端 payment_records._id (baobei-precreate 返回)
}
```

**CRM `payment_records` 集合**：保持 single source of truth，新加 `payMode='miniprogram_sqb_preorder'` 枚举值即可。

**CRM `contracts` 集合**：0 改动（`refundAmount` 字段已存在）。

### 5.2 单元/集成（baobei 端）

- [ ] `createPreOrder` 调通（测试环境）
- [ ] `generatePreOrderShareUrl` 生成二维码 + 上传云存储
- [ ] `paymentCallback` 接收推送 + SHA256WithRSA 验签通过/失败两条路径
- [ ] `queryPreOrder` 状态轮询（每 2 秒，最多 5 分钟）
- [ ] `refundPreOrder` 退款链路（包含推送回流）

### 5.3 端到端

- [ ] 销售在 baobei 端「我的合同 → 详情」点「代客下单」→ CRM 建 pending → SQB 生成二维码 → 客户用支付宝扫码 → 支付成功 → baobei webhook → CRM `payment-confirm` → CRM payment_records.status=paid → baobei 详情状态自动刷新
- [ ] 客户主动在 baobei 端「我的订单 → 详情」点「扫码支付」（如选 B 方案）→ 同上
- [ ] 退款：销售/客户点「申请退款」→ baobei `refundPreOrder` → CRM `refund-confirm` → 状态回流

### 5.4 验收口径

- 客户从扫码到付款完成 ≤ 30 秒（理想 ≤ 10 秒）
- baobei 端状态自动刷新延迟 ≤ 5 秒
- 退款到账时效（收钱吧侧 SLA，1-3 工作日）

## 9. CRM 端点 OpenAPI 草案（请 CRM 专家确认）

### `POST /api/payment-records/baobei-precreate`

鉴权：`X-Service-Secret`

请求：
```json
{
  "phone": "18604592681",
  "contractId": "6a4e2855e8de26bd7fca55a8",
  "orderCategory": "housekeeping",
  "paymentSequenceNo": 1,            // 可选，V2 多笔支付时传
  "amountCents": 200,                // 单笔金额（分）
  "subject": "安得褓贝-合同支付-定金",
  "channel": "alipay"                 // alipay | wechat (预期通道)
}
```

响应：
```json
{
  "recordId": "65a4d...",            // payment_records._id
  "clientSn": "ANDEBB20260709120000..."  // 商户订单号 (preOrderId 前身)
}
```

### `POST /api/contracts/:id/refund-confirm`

鉴权：`X-Service-Secret`

请求：
```json
{
  "phone": "18604592681",
  "paymentRecordId": "65a4d...",     // 可选，对应 payment_records._id
  "sqbRefundSn": "refund_sn_xxx",    // 收钱吧退款流水号
  "refundAmountCents": 200,           // 退款金额（分）
  "refundedAt": "2026-07-09T12:34:56+08:00"
}
```

响应：
```json
{ "ok": true }
```
